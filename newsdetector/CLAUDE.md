# CLAUDE.md — 뉴스감지기 작업 기준

이 프로젝트에서 작업할 때 반드시 지켜야 할 기준을 요약한다.

## 기준 문서
- 이 프로젝트의 기준 문서는 `docs/` 폴더다.
- 작업을 시작하기 전에 항상 아래 문서를 먼저 읽는다.
  - `docs/channel.md` — 채널 정체성과 벤치마킹 원칙, 저작권 규칙
  - `docs/script_rules.md` — 대본 규칙
  - `docs/sourcing.md` — 소재 발굴 규칙
  - `docs/title_rules.md` — 제목 공식

## 최종 목표
소재 1건당 아래 세 가지를 `output/YYYY-MM-DD/<소재명>.md` 파일 하나로 뽑는다.
썸네일은 사람이 직접 만들기 때문에 범위에서 뺀다.

1. 대본: `docs/script_rules.md` 의 8단계를 따르고 `validator` 를 통과한 것
2. 제목 후보 3개: `docs/title_rules.md` 를 따른다
3. 영상 소스 추천: JTBC 뉴스와 MBC뉴스 공식 유튜브 채널의 영상만, 3~5개

### 출력 파일 형식
```
## 소재 요약 (한 줄)
## 기사 짝: A(주인공 쪽) 제목+URL / B(악역 쪽) 제목+URL
## 대본
## 제목 후보 3개
## 영상 소스 (채널명 / 영상 제목 / 업로드일 / URL / 어느 대본 단계에 쓸지)
## 사실 확인 목록 (대본 속 숫자와 인과 문장별 출처 URL)
```

## 폐기된 옛 기준
- 옛 기준(7단락 구조, 반박 단락, 535~580자 분량 등)은 폐기되었다.
- 폐기된 기준은 어떤 결정에도 다시 쓰지 않는다.

## 사실 경계
- 평가와 프레임은 세게 써도 된다. (참교육, 박살, 딱 걸렸다 등)
- 그러나 숫자(금액, 비율, 건수, 기간)와 인과("~때문에", "~덕분에", "~해서")는
  반드시 기사로 확인된 것만 쓴다.
- 확인되지 않은 통계, 추정된 인과, 부풀린 숫자는 금지한다.
- 제목도 같은 기준을 따른다.

## 저작권
- 영상 소스는 저작권이 있으므로, JTBC·MBC 등 원 출처 표기를 반드시 유지한다.
  자세한 규칙은 `docs/channel.md` 를 본다.

## 단계 순서
1. **1단계 (완료)**: 프로젝트 뼈대와 문서
2. **1.5단계**: 최종 목표와 단계 계획 문서화 (이 문서, README, `docs/title_rules.md`,
   `docs/channel.md` 저작권 조항, `.env.example`)
3. **2단계**: `config/` yaml 채우기 (분량 TBD 확정 포함)
4. **3단계**: `src/validator.py` 구현 (대본 린터)
5. **4단계**: `src/scorer.py` 구현 (기사 짝 채점기)
6. **5단계**: `src/writer.py` + 작업 방식
   - 별도 API를 쓰지 않는다.
   - `writer.py` 는 scorer 가 고른 기사 짝과 `docs/` 규칙을 묶어 "작성 지시서"를 만든다.
   - Claude Code 세션이 그 지시서로 대본과 제목을 쓴다.
   - 결과는 `validator.py` 로 자동 검사한다.
7. **6단계**: `src/video_finder.py` (YouTube Data API v3 로 영상 추천)
   - API 키는 `.env` 의 `YOUTUBE_API_KEY` 에서 읽는다.
   - 채널은 JTBC 뉴스(@jtbc_news)와 MBC뉴스(@MBCNEWS11) 두 개만 쓴다.
   - 채널 ID 는 `channels.list` 의 `forHandle` 로 조회해 `config/video_sources.yaml` 에 저장한다.
     조회에 실패하면 멈추고 보고한다. 추측한 ID 를 쓰지 않는다.
   - 기사 짝의 핵심 인물명과 사건 키워드로 검색한다. 최근 30일 영상을 우선한다.
   - 인물 얼굴이 나올 만한 영상(발언, 회의, 인터뷰)을 우선하고,
     대본 단계 중 어디에 쓸지(3단계 대통령 쪽 사건, 4단계 악역 등)를 붙인다.
   - 하루 할당량(검색 약 100회)을 넘지 않도록 호출 횟수를 기록한다.
8. **7단계**: `src/collector.py` 연결과 하루 1회 실행 흐름
   - 수집 → 채점 → 작성 지시서 → 대본·제목 → 검사 → 영상 추천 → `output/` 저장

## 작업 범위 규칙
- 사용자가 요청한 단계 밖의 파일은 수정하지 않는다.
- 각 단계의 완료 조건이 명확할 때만 다음 단계로 넘어간다.
